// fundamentos · representação

Como Máquinas Entendem o Mundo?

  • Como enxergam o mundo? → Matrizes de pixels (ex: 32×32×3 = 3.072 valores)
  • Como ouvem o mundo? → Séries temporais de amplitude sonora
  • Como falam com o mundo? → Probabilidades sobre tokens de vocabulário
  • Como leem textos? → Vetores de embedding em espaços de alta dimensão
TUDO é representado como matrizes de números reais
⊹ Exemplo
Uma imagem colorida de 32×32 pixels tem 3.072 entradas. Uma frase de 50 palavras, com embeddings de 768 dimensões, ocupa uma matriz de 50×768 = 38.400 valores. Um LLM como o GPT-4 opera com matrizes de bilhões de parâmetros.

// LLMs · definição

O que são LLMs?

  • Tokens: unidades básicas — palavras, subpalavras ou caracteres
  • Embeddings: representações vetoriais de tokens em espaço de alta dimensão
  • Treinamento: bilhões de textos — livros, artigos, código, web
  • Objetivo: prever o próximo token dado um contexto
P(token_{t+1} | token_1, token_2, ..., token_t) = f_θ(contexto)
⚡ Insight Central
Do ponto de vista matemático, LLMs são preditores da próxima palavra (ou token) dado um contexto. A "inteligência" emerge como subproduto de prever linguagem em escala massiva.
// LLMs · arquitetura

Por que Transformers?

Antes — RNNs e LSTMs

Dominavam o processamento sequencial. Problema: dificuldade para lidar com dependências de longo prazo. Processamento serial.

Solução — Transformers (2017)

Mecanismo de atenção conecta todas as palavras diretamente. Processamento paralelo. Escalável a bilhões de parâmetros.

Attention(Q, K, V) = softmax( QKᵀ / √d_k ) · V
  • Q = Queries · K = Keys · V = Values
  • Cada palavra "olha" para todas as outras e pondera sua relevância
  • Múltiplas "cabeças" de atenção operam em paralelo (Multi-Head Attention)
// LLMs · arquitetura transformer

Encoder e Decoder

// Encoder
  • Recebe a sequência de entrada (frase)
  • Embedding + Posição
  • Self-Attention: cada palavra "olha" para todas
  • Feed-forward por camada
  • Gera representação contextualizada
// Decoder
  • Recebe representações do Encoder
  • Masked Self-Attention (não vê futuro)
  • Atenção cruzada sobre o Encoder
  • Feed-forward por camada
  • Prevê o próximo token
⊹ Embeddings Posicionais
Transformers não têm noção intrínseca de ordem. Por isso, vetores de posição são adicionados aos embeddings — permitindo ao modelo capturar a sequência das palavras.
// LLMs · limitações

O Problema das Alucinações

  • Contexto: conjunto matricial com valores comuns a um determinado assunto
  • Problema: matrizes com valores próximos mas diferentes por ruído
  • Resultado: o modelo "interpola" e gera informação plausível, porém falsa
⚠ Alucinação
Respostas factualmente incorretas apesar do tom confiante e legítimo. O modelo é treinado para produzir textos plausíveis — não necessariamente verdadeiros. "Mentindo com confiança."
  • Falta de grounding: LLMs não consultam fontes por padrão
  • Cálculos encadeados: erros se propagam com aparência de certeza
  • Citações e eventos recentes: podem ser fabricados

O que é RAG?

Modelos que complementam LLMs utilizando a sequência de entrada x para recuperar documentos z e os utilizam como contexto adicional ao gerar a sequência y.

Fidelidade

A adição de informação (x+z) auxilia na geração de respostas contextualmente apropriadas.

Referências

Acesso irrestrito aos documentos (z) habilita respostas associadas a fontes controláveis.

Baixa Alucinação

Aplicações de LLM com RAG têm menor probabilidade de gerar respostas incorretas.

// RAG · avaliação

Métricas de Avaliação do RAG

// Generation
  • Fidelidade — o quão factualmente correta a resposta gerada está
  • Relevância — o quão relevante a resposta é em relação à pergunta
// Retrieval
  • Precisão do Contexto — a razão entre sinal e ruído do contexto recuperado
  • Revocação do Contexto — quanto da informação relevante foi recuperada
⊹ Arquitetura Típica
Ferramentas como LangChain + ChromaDB (vector store) + OpenAI/Anthropic formam a base de sistemas RAG: Document Loader → Embedding Model → Vector DB → Retriever → LLM → Resposta.
